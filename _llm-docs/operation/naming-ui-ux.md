# UI/UXデザイン表記規約

## 概要

本ドキュメントは、UIデザインにおける表記の統一性を保つための規約です。ユーザー体験の一貫性を確保し、表記揺れによる混乱を防ぐことを目的とし、同一画面・同一機能では必ず同じ表記を使用します。

## Protocol：全角と半角の境目

最優先で守るルール。本ドキュメント・仕様書・コード内のユーザー向け文言・コミットメッセージ等、本プロジェクトに関わるすべての日本語テキストに適用される。

- 全角文字と半角文字の境目にスペースを入れない（例：`microCMS管理画面`、`URLパラメータ`、`Cookieの挙動`、`有効期限1時間`）
- 半角文字どうしの間にはスペースを入れる（例：`Next.js App Router`）
- バッククォートで囲ったコードトークンも半角として扱う（例：`interview`コンテンツ）

## 文体

- **敬語レベル**：丁寧語（です・ます調）を基本とする
- **表記**：ひらがな・カタカナ・漢字のバランスを考慮
- **トーン**：親しみやすく、専門用語は最小限に

## 用語の対応表

### 認証関連

| 推奨表記   | 避けるべき表記         | 使用場面             |
| ---------- | ---------------------- | -------------------- |
| ログイン   | サインイン、ログオン   | ログイン画面、ボタン |
| ログアウト | サインアウト、ログオフ | ログアウトボタン     |
| アカウント | ユーザー、会員         | アカウント設定画面   |
| パスワード | パスワード、暗証番号   | 入力フィールド       |

### アクション関連

| 推奨表記   | 避けるべき表記   | 使用場面         |
| ---------- | ---------------- | ---------------- |
| 登録       | 登録する、Submit | 新規登録ボタン   |
| 変更       | 更新、編集、修正 | 情報変更ボタン   |
| 削除       | 消去、取り消し   | 削除ボタン       |
| 検索       | サーチ、探す     | 検索ボタン       |
| 選択       | 選ぶ、チェック   | 選択ボタン       |
| OK         | 決定、OK         | 確定ボタン       |
| キャンセル | 取り消し、戻る   | キャンセルボタン |

### 状態・ステータス関連

| 推奨表記 | 避けるべき表記       | 使用場面       |
| -------- | -------------------- | -------------- |
| 完了     | 終了、済み           | ステータス表示 |
| 処理中   | 実行中、ローディング | 処理状態表示   |
| エラー   | 失敗、NG             | エラー表示     |
| 必須     | 必須入力、必要       | 必須項目マーク |

### 単位・数値表記

| 項目 | 推奨表記     | 例            |
| ---- | ------------ | ------------- |
| 日付 | YYYY年M月D日 | 2024年3月15日 |
| 時刻 | HH:MM        | 14:30         |

## メッセージ文言の型

### 確認メッセージ

- **推奨**：「〜してもよろしいですか？」
- **例**：「この内容で登録してもよろしいですか？」

### 完了メッセージ

- **推奨**：「〜が完了しました。」
- **例**：「登録が完了しました。」

### エラーメッセージ

- **推奨**：「〜できませんでした。〜してください。」
- **例**：「ログインできませんでした。入力内容をご確認ください。」

## 表記の細部ルール

### カタカナ

- 外来語は原則カタカナ表記
- 長音符号「ー」は省略しない（例：ユーザー、サーバー）

### 記号

- 句読点は「、」「。」を使用
- カッコは全角「（）」を基本とする
- 数字は半角を使用
